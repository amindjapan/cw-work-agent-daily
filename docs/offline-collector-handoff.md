# Collector 取得状態と非公開受け渡しの限定修正

この変更は、隔離環境で人工データを検証する準備実装です。本番収集・転送・公開・runner 接続を有効にしません。

## 既存資料との互換性

`generatedAt` / `generatedAtJst` は従来どおり収集開始時の値です。期限の判定基準も同じ時刻を使います。`safeCandidates` は従来の機械候補数を保持し、詳細取得に失敗した検索要約の候補を含み得ます。安全性や応募許可の認定ではありません。収集できなかった `null` と、正常に確認した `0` を区別します。

新しい summary には次の `collection` を追加します。従来のキーは削除しません。新フィールドがない旧資料は、試行完了や詳細確認済み候補数を `UNKNOWN` として扱い、`generatedAt` から完了時刻を推定しません。過去の資料は書き換えません。

```json
{
  "schemaVersion": 1,
  "status": "attempts_completed",
  "startedAt": "2026-10-29T14:59:58.000Z",
  "attemptsCompletedAt": "2026-10-29T15:00:03.000Z",
  "decisionAsOf": "2026-10-29T14:59:58.000Z",
  "search": { "planned": 1, "attempted": 1, "succeeded": 1, "failed": 0, "notAttempted": 0 },
  "details": { "observed": 2, "attempted": 2, "succeeded": 1, "failed": 1, "notAttempted": 0 },
  "candidates": { "machine": 2, "detailConfirmed": 1, "detailUnconfirmed": 1 }
}
```

この例は人工データです。`startedAt` と `decisionAsOf` は `generatedAt` と一致します。`attemptsCompletedAt` は検索と詳細の試行ループを終えた時刻であり、保存・公開・日次処理全体の成功時刻ではありません。日付を跨いでも開始時刻を置き換えません。完了時計が無効または開始より前なら `invalid_collection_clock` で停止し、完了時刻を補いません。

検索の `planned` は指定されたキーワード検索の数です。`succeeded` は取得と解析が成功した試行、`failed` は HTTP エラー・例外・不完全な解析を含む試行です。部分解析で得た案件を保持しても、その検索を完全成功にはしません。

詳細の `observed` は検索で観測した重複除去後の案件数です。`attempted = succeeded + failed`、`observed = attempted + notAttempted` です。`notAttempted` には既存リスク除外・80件上限の対象外と、アダプターが明示的に `not_attempted` を返した案件を含みます。アダプターを呼んでも、不正な別IDや成功情報なしの戻りは解析失敗に数えます。検索範囲・アクセス頻度・詳細80件上限は変えません。

`candidates.machine` は `safeCandidates` と同じです。`detailConfirmed` は、そのうち当該実行で同一案件の詳細取得と解析が成功した件数です。残りが `detailUnconfirmed` です。候補が存在するか不明なら3値とも `null` を保持します。

## 推薦条件と公開範囲

推薦には、今回呼び出した詳細アダプターによる同一ID・正規URL、明示的な `detailFetch.ok: true` / `outcome: success` / HTTP 2xx、非空本文、開始から試行完了までの `detailCheckedAt` を必要とします。古い時刻だけの戻り、403、429、例外、別ID、本文解析失敗では推薦しません。従来の成功fixtureも明示的な成功情報を渡す形へ更新しています。

機械候補が残っても詳細確認済み候補がなければ、候補なしと混同せず「詳細未確認のため推薦なし」と表示します。取得・解析成功は、AI利用許可・採算・応募資格・安全性の確認済みを意味しません。

公開投影は従来の許可ファイルと既存業務情報に、新しい時刻・固定状態・件数だけを明示許可します。内部の候補一覧、本文一覧、snapshot、private record、発注者レビュー、秘密フィールドは追加しません。新集計の未知フィールドは再帰的に除外し、既知フィールドの型・日付・件数矛盾は staging 作成前に拒否します。旧 summary はバイト列を維持し、新集計も投影で内容が変わらなければバイト列を維持します。

## 明示した保存済み資料の純粋な照合

`src/verify-private-candidates.js` の API は次のとおりです。

```javascript
const { verifyPrivateCandidateHandoff } = require("./src/verify-private-candidates");
const result = verifyPrivateCandidateHandoff({
  recordBytes,    // 呼出し元が渡す保存済み private record の UTF-8 Buffer または文字列
  snapshotBytes,  // 同じ実行の保存済み snapshot
  summaryBytes,   // 同じ実行の保存済み summary の実バイト列
  now: "2026-10-29T15:00:04.000Z",
  expectedExecutionId // 任意。既知の UUID v4 があるときに照合
});
```

関数はネットワーク、ファイルの読書き、transport、保存処理、暗黙の現在時刻を呼びません。各入力は5 MiB以内です。呼出し元が読み出し済みの資料と判定時刻を明示します。公開・CI・runner の通常経路へは接続していません。

照合対象は record 自己ハッシュ、snapshot の runId と内容ハッシュ、保存済み summary の実UTF-8バイトSHA256、実行ID、候補ID集合、件数、同じ候補の正規参照・取得時刻・固定理由コードです。同件数のID入替え、重複、欠落、再署名した未知フィールド、時刻矛盾も拒否します。新 summary の詳細確認件数は snapshot の詳細試行証拠と照合します。ファイルを再シリアライズすると summary の実バイトハッシュは変わるため、元バイトを渡してください。

| status | 意味 |
| --- | --- |
| `verified` | 明示された資料のID・件数・ハッシュが整合 |
| `unknown` | 資料は整合したが、取得件数・候補数が未確認の `null` |
| `incomplete` | record / snapshot / summary のいずれかが未提示。保存途中や受け渡し不足を成功にしない |
| `expired` | 抽出から30×24時間に到達。`requiresReview: true`、一覧を返さない |
| `invalid` | 不正JSON、未知schema、ハッシュ・ID・件数・時刻などの不整合 |

返すのは固定状態・固定の問題コード・照合状態・`collectionCompletion` だけです。候補一覧や入力自由文は返しません。`collectionCompletion` は検証済み試行完了時刻、または `UNKNOWN` です。旧資料では `verified` でも完了時刻は `UNKNOWN` です。

ハッシュ一致は入力資料どうしの整合を示すだけです。署名による真正性、現在ソースとの一致、保存先の完全列挙、永続性、非共有状態、全処理成功は認定しません。`collector.sourceSha256` は保存済みの主張として形式を検査し、現在のファイルを読みません。検索範囲が部分取得なら、整合が取れていてもサイト全体や設定範囲の完全取得とは呼びません。

## 導入前に残る条件と完了ベースの巡回設計

通常CLIは追加保存を受け取らず、ローカル opt-in、CI拒否、100候補 / 60記録 / 5 MiB / 30日の既存上限を維持します。Driveアダプターは synthetic-only のままです。runner 接続、Drive専用記録の完全列挙、認証・権限、Windows ACL、所有者のみの非共有状態、raw全文読戻し・実バイト照合は未実証または未確定の条件として残します。

導入後の巡回は、単に定刻の `latest` を読むのではなく、開始基準日、今回の実行ID、試行完了時刻、保存済み3資料の照合を確認する設計にします。異なる実行や前日の資料、保存途中、失敗や `UNKNOWN` はそれぞれ明示します。日付跨ぎでも開始日と完了日を混同しません。完了の観測だけで安全審査済みや応募可能と判断しません。

この変更は収集・判定と検証仕様に限定され、cron・収集頻度・再実行・保存や共有設定を変更しません。本番の非公開受け渡しには保存先と実行環境の条件確認が必要です。

## 検証と戻し方

`npm test` は人工fixture、模擬取得、模擬transport、隔離した一時ディレクトリで実行します。テスト専用CIは `npm run daily`、実案件収集、Drive書込み、snapshotのcommit、Pages公開を実行しません。lint・型検査の設定や外部依存関係はありません。

本番への反映はないので運用上の戻し操作は不要です。隔離変更を取り消す場合は、対象コミットの `src/daily.js`、`src/prepare-public-artifact.js` と対応テスト・文書を戻し、追加の verifier と専用テスト・この文書を外します。提示パッチの逆適用は、対象コミットと一致する隔離checkoutで `git apply --reverse --check` を先に確認してから行えます。実データ、過去成果物、既存保存記録は削除しません。既存の正常ページ解析修正や非公開保存の制限を戻しません。

## 再確認・デバッグ v2

v2では取得状態と公開・非公開資料の整合性について、人工入力による境界条件の回帰を追加しています。

v2では、暦あふれ・timezone欠落を詳細成功にせず、有効なoffset日時をUTCへ正規化します。詳細アダプターには入力のコピーを渡し、取得前の案件IDを破壊変更できないようにします。同じIDの数値と文字列は正規IDに統一し、失敗や未来の詳細時刻をsnapshotの観測時刻へ流しません。明示的に検索由来の本文や、markupを除くと空になる本文を詳細成功にしません。検索結果で公開ID検査後に案件を除外した場合は、取得範囲の解析不足として記録し、正常ゼロと区別します。

不正な掲載期限は推薦から除外します。期限なしとして扱うのは未指定・null・空文字だけです。従来の機械候補数と詳細確認済み候補数は保持するため、詳細確認済みでも推薦条件を確認できず推薦がない場合があります。表示もその状態を区別します。

既存の期限判定基準は保持しています。指定日の日本時間 `23:59:59.000` を超えると、同日の最後の999ミリ秒も期限切れ扱いです。これは従来挙動の制約であり、v2で日末を翌日00:00排他へ変更していません。判定基準を収集完了時刻へ動かしたり、過去成果物を再計算したりもしません。

公開側は新しいcollection付き資料に限り、集計と公開試行の整合、nullと確定件数の混在、推薦の正規ID/URL・詳細時刻・期限・スコア・応募件数・本文を追加検査します。旧形式の有効な資料のフィールドやバイト列は維持します。

純粋検証は、UUID/hashを配列から暗黙変換して受理せず、候補以外を含む全詳細成功の2xx・同実行時刻・本文由来・非空本文hashを照合します。案件のdetail状態と試行を双方向に照合し、機械判定理由・レベル・スコアの矛盾、推薦時刻・期限hashとsnapshotの不一致も拒否します。入力のaccessorを評価せず拒否し、入力バイトをコピーして検証とhashに同じ値を使います。

公開と非公開のJSON読取りは、I/Oを持たない共通の `src/strict-json.js` を使用します。不正UTF-8、BOM、重複した復号後キーを拒否します。これにより、後の重複値だけをJSON.parseで確認し、前の内部文字列を元バイトコピーで公開してしまう経路を閉じます。非公開照合では損失変換を起こす文字列と共有メモリーBufferも拒否します。単なるハッシュ一致を真正性や完全取得の証明とはしません。

本番接続・保存・公開、既存保存上限とopt-in/CI禁止、Drive synthetic-only、収集範囲と頻度の制限は維持します。Node22/Ubuntuのテスト専用CIは既存npm testと構文検査だけを実行し、実リンク3件の成功とスキップ0件を確認します。PCの権限変更や実収集は行いません。コードを戻す場合は対象の変更commitをrevertし、新しいstrict helperとそのテストも対応して戻します。実データや過去成果物は削除しません。
